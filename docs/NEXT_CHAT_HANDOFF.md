## 5. 피해 계산 원칙

- 같은 이름의 스탯은 중첩 수를 합산해 하나의 계수를 만든다.
- 이름이 다른 피해 계수는 기본적으로 서로 곱한다.
- 같은 패시브를 중첩마다 복리식으로 곱하지 않는다.

### 출력 증폭

```text
모든 피해 계수 = 1 + 출력 증폭 중첩 × 0.10
```

### 거성 사냥꾼

```text
중간보스·보스 피해 계수 = 1 + 거성 사냥꾼 중첩 × 0.15
```

### 동시 보유 예시

```text
출력 증폭 1중첩 + 거성 사냥꾼 1중첩
보스 대상 배율 = 1.10 × 1.15 = 1.265
```

현재 `progression-expansion.js`가 거성 사냥꾼 ×1.15를 직접 적용한다. 이전 버전처럼 뒤쪽 파일에서 옛 배율을 다시 상쇄하는 구조로 되돌리지 않는다.

## 6. 경험치 패시브

- 성운 통찰: 경험치 획득량 +10%
- 개척 계약: 적 체력 +10%, 경험치 획득량 +30%
- 두 보너스는 같은 `경험치 획득량` 스탯이므로 합산한다.

```text
경험치 배율
= 1
+ 개척 계약 중첩 × 0.30
+ 성운 통찰 중첩 × 0.10
```

```text
적 체력 배율
= 기본 시간 성장 × (1 + 개척 계약 중첩 × 0.10)
```

최종 함수는 `performance-guard.js`의 `enemyHpMult`, `xpMult` 대입까지 확인한다.

## 7. 레벨과 위협

레벨 요구 경험치:

```text
10 + 3.8 × level + 1.35 × level^1.34
```

- 레벨당 피해 +1.1%
- 위협은 생존 시간 1분마다 상승
- 위협 상승 시 적 체력·피해·이동속도·원거리 공격 빈도 증가
- 후반 난도는 개체 수만이 아니라 적 스탯으로도 높인다.

## 8. 정예 체력과 보상

- 중간보스: 기존 체력 유지
- 일반 보스: 이전 최종 체력 ×0.88
- 공허 보스: 이전 최종 체력 ×0.92
- 초월체: 체력 너프 미적용

정예 등장 순환:

```text
중간보스 → 중간보스 → 보스
```

- 기존 정예가 살아 있어도 다음 시간이 되면 추가 등장
- 동시 정예 4명부터 다음 등장 연기
- 초월체 직전에는 일반 정예 신규 등장 중단

보상:

- 중간보스: 보유 장비 +1 또는 일반 패시브 +1
- 일반 보스: 특수 패시브 또는 보유 무기 특수효과
- 공허 보스: 공허 전용 보상
- 초월체: 고유 유산

## 11. 현재 성능 구조

### 상시 최적화

`performance-guard.js`와 `systems-base.js`에서 평상시 화질을 유지하면서 계산량을 줄인다.

- 숫자형 공간 해시 격자 사용
- 유한 사거리 `nearestEnemy`가 인접 격자만 탐색
- 적 ID→객체 색인을 매 프레임 구성
- 부메랑 목표 탐색에서 반복 `Array.find` 제거
- 종료된 아군 투사체 객체를 최대 320개 풀에 보관해 재사용
- 일반 적과 투사체 외형을 OffscreenCanvas 또는 숨은 Canvas에 한 번 렌더링
- 광원·그라디언트·꼬리를 포함한 캐시 이미지를 매 프레임 `drawImage`로 재사용
- 화면 밖 개체 렌더링 생략
- 화면 좌표를 정수로 반올림
- 배열은 제자리 압축 우선
- 경험치 결정 상한 초과 시 값 병합

### 캐시 주의점

- 투사체 캐시 키: 종류, 반지름, 색상
- 일반 적 캐시 키: 적 유형, 반지름, 색상, 공허 유체의 위상 구간
- 보스와 중간보스는 고유 애니메이션을 보존하기 위해 기존 벡터 렌더러 유지
- 캐시 크기를 무제한으로 키우지 않는다.
- CSS 색 문자열에 단순히 8자리 HEX 알파값을 덧붙이지 않는다. HEX와 rgba 문자열을 모두 안전하게 처리해야 한다.

### 과부하 대응

화질 하락은 상시 해결책이 아니라 마지막 안전장치다.

- 경고 상태: 개체 예산과 파티클 생성량만 완만하게 제한
- 긴급 상태: 약 33ms 이상의 프레임 또는 누적 지연이 지속될 때만 배경·효과 일부 단순화
- 심한 지연이 1.8초 이상 지속될 때만 Canvas 내부 해상도 80%
- 안정 상태가 7초 이어지면 원래 해상도로 복구

기본 DPR 상한:

- 데스크톱: 1.75
- 모바일: 1.35

## 13. WebGL·PixiJS 이관 의미

- 새 저장소를 만들 필요가 없다.
- 같은 GitHub 저장소와 같은 Cloudflare Pages 배포를 유지할 수 있다.
- 게임 규칙, 적 AI, 피해 계산, 보상, 입력과 저장 데이터는 가능한 한 유지한다.
- 교체 대상은 Canvas 2D의 `draw*` 렌더링 계층이다.
- PixiJS는 WebGL/WebGPU 위에서 Sprite, Container, ParticleContainer 등의 상위 API를 제공한다.
- raw WebGL은 버퍼·텍스처·셰이더·드로 콜을 직접 관리해야 하므로 이 프로젝트에는 PixiJS가 현실적인 선택이다.

권장 단계:

1. PixiJS 렌더러를 기존 Canvas 2D와 함께 초기화
2. 아군 투사체와 파티클부터 Pixi Sprite·ParticleContainer로 이전
3. 일반 적과 배경 이전
4. 광선과 중력 우물 이전
5. 보스 특수효과 이전
6. 동작과 비주얼이 동일해지면 기존 Canvas 렌더 함수 제거

한 번에 게임 전체를 다시 만드는 것이 아니라, 같은 상태 배열을 두 렌더러가 읽는 하이브리드 단계로 점진 이전할 수 있다.

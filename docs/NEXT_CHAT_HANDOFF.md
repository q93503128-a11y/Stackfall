## 2. 사용자의 절대 작업 원칙

1. **이미지 생성 금지.** 사용자가 이미지 생성이 아니라 저장소 코드 수정을 요구한다.
2. README와 게임 디자인 문서를 먼저 읽는다.
3. 가능한 한 기존 원본 모듈을 직접 수정한다. 파일 맨 아래에서 기존 함수를 계속 감싸는 임시 래퍼·덮어쓰기 파일을 새로 추가하지 않는다.
4. 이미 존재하는 후반 보정 파일이 많으므로, 최종 실행 함수를 반드시 로딩 순서 기준으로 추적한다.
5. 인게임에 패치 내역, 개발 설명, “코드로 생성됨” 같은 잡설을 넣지 않는다.
6. 인게임 설명은 짧고 실제 효과와 정확히 일치해야 한다. 불필요한 TMI를 피하고 명사형·간결한 문장을 선호한다.
7. 디자인은 우주적이고 광활하며 심오한 분위기, 아름다운 빛·궤적·성좌·혜성·공허 연출을 우선한다.
8. 단순 수치 증가보다 중첩마다 행동이 달라지는 시각적·기계적 효과를 선호한다.
9. 성능을 무시하지 않는다. 장시간 런에서 적·경험치·투사체·파티클·DOM 갱신이 누적되지 않게 한다.
10. 변경 후 문법 검사와 실제 런타임 테스트를 한다. 확인하지 못한 사항은 확인했다고 말하지 않는다.

## 3. 핵심 게임 규칙

- 장르: Vampire Survivors 계열의 웹 생존 액션 + 장비 중첩 빌드.
- Muck/PokéRogue처럼 한 런 안에서 장비와 패시브를 계속 쌓는다.
- 일반 장비 슬롯은 최대 6칸이다.
- 기본 무기 `코어 펄스`는 일반 장비 슬롯과 별도로 항상 존재하고 강화·중첩된다.
- 패시브는 개수 제한이 없고 각 패시브마다 최대 중첩만 존재한다.
- 같은 장비 중복 획득 가능.
- 모든 장비는 1~6중첩마다 효과가 존재한다. 2·4·6만 효과가 있는 구조로 되돌리지 않는다.
- 장비는 공격형만 있는 것이 아니다. 방어·제어·지원 장비도 포함된다.
- 모든 자동 공격은 기본적으로 플레이어 몸체 기준 가장 가까운 적을 우선한다.
- 짝수 발사에서는 최소 한 발이 표적 중심을 정확히 향해야 한다.
- 화면 하단에는 기본 무기와 장비, 중첩 수, 실제 쿨타임 원형 표시가 나타난다.
- 지속형 장비처럼 쿨타임이 없는 장비에는 쿨타임 원형 표시를 하지 않는다.

## 4. 현재 장비

### 기본 무기

- 코어 펄스: 자동 추적 광자탄. 별도 기본 무기 칸. 1~6중첩.

### 일반 장비

1. 펄스 블레이드
   - 플레이어 주변 지속 공전 칼날.
   - 공격속도·주기 감소가 피해 틱에 적용된다.
   - 투사체 속도 패시브는 공전 속도로 적용된다.
2. 별빛 캐스터
   - 폭발성 별빛 탄환.
   - 코어 일반 탄환과 구분되는 폭발·별빛 꼬리.
3. 성광 장벽
   - 보호막·피해 감소·반격.
   - 예전 이름 불워크 드론을 사용하지 않는다.
4. 중력 우물
   - 적 집속, 고중첩 지속 피해, 6중첩 다중 우물.
   - 일반 중력 우물 외형은 얇은 타원형 중력 렌즈.
5. 혜성 창
   - 긴 창 형태의 관통 투사체. 화살 모양으로 만들지 않는다.
6. 성좌 프리즘
   - 화면 끝까지 뻗는 관통 광선.
7. 시간 고리
   - 주변 감속, 주기 가속, 고중첩 시간 파동.
8. 성운 부메랑
   - 지정 표적을 반드시 공격하는 곡선 왕복 무기.
   - 경로의 적도 타격.
   - 표적 타격 후 급발진하지 않고 자연스럽게 턴한 뒤 플레이어에게 귀환.
   - 출발과 귀환 각각 피해.

## 6. 맵 이벤트

각 이벤트는 독립 주기를 가진다. 동시에 여러 이벤트를 활성화하지 않는다.

### 성운 보관소

- 가장 짧은 주기.
- 첫 등장 약 42초.
- 이후 대략 55~78초.
- 전투 없이 무작위 능력 강화 3개 중 하나 선택.
- 현재 강화 예시:
  - 피해 +10%
  - 공격 주기 -8%
  - 자석 범위 +45
  - 최대 체력 +10%
  - 이동속도 +8%
  - 투사체 속도 +12%, 크기 +8%
  - 보호막 충전 강화
  - 연쇄 유지시간 +28%

### 추락한 우주선

- 두 번째로 긴 주기.
- 첫 등장 약 78초.
- 이후 대략 95~135초.
- 접근 즉시 강제 이벤트 잡몹전.
- 플레이어 주변 격리 전장을 생성하고 밖으로 나가지 못하게 한다.
- 전용 강화 잡몹 3웨이브.
- 보상 예시:
  - 서로 다른 패시브 2종 +1
  - 무작위 보유 무기 +2
  - 최대 체력 12% 증가와 완전 회복
  - 주기적 자동 보호막 강화

### 공허 균열

- 가장 긴 주기.
- 첫 등장 약 132초.
- 이후 대략 170~230초.
- 접근하면 입장 여부 선택.
- 입장 시 공허 차원으로 전환 애니메이션 후 전용 공허 보스전.
- 일반 보스 보상과 중복되지 않는 전용 보상:
  1. 보유 중인 모든 무기 +1중첩
  2. 서로 다른 무작위 패시브 3종 +1중첩
  3. 공허 각인: 모든 피해 +12%, 공격 주기 6% 단축
- 공허 보스 처치 후 현실 우주로 돌아오는 전환을 거친 뒤 보상 화면.

### 출현 규칙

- 기본 정예 순서: 중간보스 → 중간보스 → 일반 보스.
- 종류는 셔플 백에서 무작위 선택하며 같은 개체가 즉시 반복되는 것을 줄인다.
- 초반에는 정예가 동시에 겹치지 않는다.
- 후반에는 중간보스 2마리, 보스 호위 중간보스 등 복합 편성 가능.
- 화면 밖 보스·중간보스는 방향 화살표, 이름, 거리를 표시한다.
- 너무 멀어진 적은 기존 방향을 유지하면서 안전 거리로 복귀한다.

### 보스 패턴 차별화

최근 패치에서 색만 다른 탄막 복제를 줄이고 전용 능력을 추가했다.

- 일식의 군주: 회전 절단선과 일식 영역.
- 성운의 세라프: 회복 파동, 성광 탄막, 소환.
- 맥동성의 심장: 동심원 지연 폭발과 이중 맥동 탄막.
- 성간의 레비아탄: 대형 돌진과 항적 지뢰.
- 무한 기록자: 예측 십자선, 공간 이동, 기록 포격.
- 태양관의 군주: 회전 태양 광선과 유성 지대.
- 성뢰의 여왕: 순간이동, 예측 낙뢰, 고속 탄막.
- 무효기관 제로: 플레이어 투사체 삭제·변환과 격자 공격.
- 심연의 포식체: 흡입, 투사체 포식·회복, 공허 토출.
- 공허의 예언자: 플레이어 이동 예측 공격.
- 무광의 직조자: 공간 거미줄.
- 별무덤의 군주: 강화 소환과 묘역 폭발.
- 역설의 쌍둥이: 두 개체가 서로 다른 패턴과 연결 공격.

`쌍성의 거울`과 `역설의 쌍둥이`는 실제로 두 개체가 등장한다. α·β 이름을 표시하며 두 몸체를 모두 처치해야 보상이 한 번 지급된다.

## 8. 초월체

- 20분, 40분, 60분… 생존 시간의 정확한 배수에 등장.
- 등장 직전 현재 필드의 일반 적·정예·탄환·우물·이벤트를 정리한다.
- 초월체 전투 중 자동 잡몹·일반 보스·중간보스·맵 이벤트 생성 금지.
- 초월체 자신의 소환 패턴만 허용.
- 처치해도 런은 끝나지 않는다.
- 같은 초월체를 다시 잡으면 전용 특수능력이 중첩 강화된다.
- 초월체도 20분 주기마다 체력·공격력·패턴 속도가 강화된다.

### 시간포식자 아트로포스

- 시간 원환·절단선·시간 붕괴.
- 보상: 시간 정지 능력 중첩 강화, 가속 회로 및 영구 주기 강화.

### 종말 항성 오메가

- 거대 항성탄·태양 방사 탄막·항성 폭발.
- 보상: 항성 폭발 능력 중첩 강화, 출력·투사체·영구 피해 강화.

### 무명의 마지막 성좌

- 성좌 연결선·별자리 절단·소환.
- 보상: 성좌 방벽 능력 중첩 강화, 최대 체력·방어·보호막 강화.

각 초월체는 전용 등장 장면, 전용 맵, 전환 애니메이션을 사용한다.

## 10. 외형과 렌더링

- 플레이어 중앙 코어는 회전하지 않는 정지형 결정 코어.
- 장비·원환·성좌·자석 범위는 서로 다른 속도와 방향으로 회전.
- 성장할수록 플레이어 주변 별·원환·공전 장식 증가.
- 보스 특수 패시브와 무기 특수효과는 지속 외형 문양을 가진다.
- 일반 중력 우물: 얇은 타원형 중력 렌즈.
- 특이점 혈맥: 자홍색 붕괴별. 일반 중력 우물과 외형을 공유하지 않는다.
- 카메라 흔들림은 일반 타격·피격에서는 거의 나타나지 않고 보스 처치·공명·초월체 등 큰 사건에 집중한다.
- 공허 입장·퇴장 후 화면 가장자리 그래픽이 누적되는 버그를 막기 위해 배경은 카메라 흔들림 변환 밖에서 항상 전체 화면을 다시 그린다.

## 11. 설정과 UI

- 한국어, 영어, 일본어, 중국어, 스페인어, 프랑스어.
- 전체 소리, 전투 효과음, UI 효과음, 배경음 각각 켜기·끄기.
- 전체·전투·UI·배경음 각각 0~100 음량 슬라이더.
- 피해량 숫자 켜기·끄기.
- 화면 흔들림 켜기·끄기.
- 기본 음량은 이전보다 높게 설정.
- 능력창은 `I` 또는 `Tab`, 왼쪽 능력 탭, 일시정지 메뉴에서 열 수 있다.
- 메인 메뉴에서는 능력 탭을 표시하지 않는다.
- 능력창은 장비·패시브·보스 패시브·무기 특수효과·성운/우주선 강화·초월체 유산과 실제 공용 스탯을 표시한다.
- 장비 HUD가 비어 보이는 회귀를 막기 위해 `weaponStacks`를 기준으로 `weaponSlots`를 매번 재구성한다.

## 12. 성능·안정화

- PC 적 약 104, 모바일 약 72 상한.
- 경험치 결정 PC 약 140, 모바일 약 90 상한.
- 초과 경험치는 기존 결정에 값으로 합쳐 총 경험치를 보존.
- 플레이어·적 투사체, 파티클, 텍스트, 충격파, 예고선, 광선 상한.
- 화면 밖 투사체 정리.
- HUD DOM 갱신 약 초당 12회.
- 비정상 좌표·NaN 개체 정리.
- 렌더·업데이트 단계를 격리해 한 효과 오류가 전체 `requestAnimationFrame`을 멈추지 않게 한다.
- 레벨업 선택은 `try/finally`로 복구되어 효과 적용 중 오류가 나도 선택창을 닫고 플레이로 돌아간다.
- `.github/workflows/js-syntax.yml`에서 모든 `src/*.js`에 `node --check`를 실행한다.

## 14. 새 채팅에서 가장 먼저 해야 할 검증

저장소를 수정하기 전에 아래를 실제 배포본 또는 로컬 브라우저에서 재현한다.

1. 시작 장비 선택 후 하단에 코어 펄스와 시작 장비가 즉시 표시되는지.
2. 레벨업으로 새 무기를 얻으면 하단 장비 슬롯과 능력창에 즉시 표시되는지.
3. 게임 시작 직후 왼쪽 능력 탭이 보이고 메인 메뉴에서는 숨는지.
4. `I`와 `Tab`으로 능력창 열기·닫기.
5. 공허 입장·클리어·현실 복귀 후 상단/좌우 테두리 아티팩트가 남지 않는지.
6. 설정 슬라이더 4개가 실제 음량과 저장값을 바꾸는지.
7. 공허 보상에서 “모든 보유 무기 +1”, “패시브 3종 +1”, “공허 각인”이 정확히 적용되는지.
8. 성운 보관소·우주선·공허 균열이 서로 다른 주기로 등장하는지.
9. 쌍성의 거울과 역설의 쌍둥이가 실제 두 몸체로 등장하며 둘 다 잡아야 보상이 한 번 뜨는지.
10. 무효기관이 지운 투사체가 같은 프레임에 피해를 주지 않는지.
11. 중력 우물과 특이점 혈맥 외형이 명확히 다른지.
12. 혜성 편대·교차 성선·종말 붕괴 등 무기 강화가 실제로 체감되는지.
13. 일반 보스와 공허 보스가 패턴을 복사해 쓰지 않는지.
14. 10분 이상 플레이에서 프레임과 메모리가 안정적인지.
15. 20분 초월체 등장 시 필드가 정리되고 일반 생성이 완전히 멈추는지.
16. 40분 두 번째 초월체와 중첩 보상이 정상인지.

## 15. 알려진 구조적 위험

- 과거 기능을 빠르게 추가하면서 후반 로딩 파일이 앞의 함수를 다시 정의하는 구조가 남아 있다.
- 새 기능을 추가하기 전에 `index.html`의 스크립트 순서와 동일 함수의 마지막 정의를 검색해야 한다.
- 특히 다음 함수는 중복 정의 이력이 있다.
  - `renderLoadout`
  - `updateHUD`
  - `updateSpawning`
  - `updateEnemies`
  - `updateProjectiles`
  - `damageMult`
  - `hasteMult`
  - `killEnemy`
  - `fireComet`
  - `spawnCoreShot`
  - `drawPlayer`
  - `drawWells`
- 앞으로는 새 `*-fix.js` 파일을 계속 늘리지 말고, 기능 단위로 원본 모듈에 통합하는 리팩터링이 필요하다.
- 현재 패치는 GitHub 원격 코드 기준으로 반영됐지만, 이 대화 환경에서는 Cloudflare Pages 배포본의 브라우저 콘솔과 장기 플레이를 직접 확인하지 못했다. 새 채팅에서는 반드시 실제 배포본 QA를 먼저 한다.

## 16. 이번 후속 작업 방식

1. GitHub 저장소와 README를 직접 읽는다.
2. 현재 HEAD에서 위 체크리스트를 점검한다.
3. 버그가 있으면 원인을 최종 실행 함수까지 추적한다.
4. 임시 덮어쓰기 대신 해당 원본 모듈을 직접 수정한다.
5. `node --check`와 브라우저 콘솔 오류 검사를 한다.
6. 모바일·데스크톱 화면을 모두 확인한다.
7. 변경 내용을 `main`에 커밋한다.
8. 인게임에 패치 내역을 넣지 않는다.
9. 작업 완료 후 실제로 확인한 것과 확인하지 못한 것을 구분해 보고한다.

첫 응답에서는 추측으로 수정하지 말고, 저장소의 현재 상태와 배포본에서 위 회귀가 남아 있는지부터 구체적으로 검사해라.

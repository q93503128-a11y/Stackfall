## 2. 매 작업의 절대 원칙

1. `README.md`, `docs/GAME_DESIGN.md`, 이 문서를 먼저 읽는다.
2. 배포본에서 재현 가능한 문제를 먼저 확인한다.
3. `index.html` 로딩 순서를 따라 최종 실행 함수를 찾는다.
4. 가능한 한 기존 원본 모듈을 직접 수정한다.
5. 새 fix/override 파일을 계속 추가하지 않는다.
6. 인게임에 패치 내역, 개발 설명, 계산식 TMI를 넣지 않는다.
7. 선택지 설명은 짧고 실제 효과와 정확히 일치시킨다.
8. 우주적이고 광활하며 심오한 분위기와 타격감을 우선한다.
9. 장시간 런에서 적, 투사체, 광선, 파티클, 경험치가 누적되지 않게 한다.
10. 코드 변경이 끝나면 문서 3종도 실제 코드에 맞게 갱신한다.
11. JavaScript 문법, 브라우저 콘솔, 데스크톱·모바일 플레이를 확인한다.
12. 확인하지 못한 항목을 확인했다고 말하지 않는다.

## 6. 공전 장비 궤도

공전 장비는 고정 반경을 각각 따로 사용하지 않는다.

- 공전 순서: 성광 장벽 → 펄스 블레이드 → 성좌 프리즘 → 유성 드론
- `orbitRadiusFor(key)`가 현재 보유 장비와 실제 크기를 계산한다.
- `orbitHalfExtent(key)`가 각 장비 외형의 반지름을 제공한다.
- 바깥 장비는 안쪽 장비의 외곽보다 충분히 바깥에 배치된다.
- 펄스 블레이드 충돌 판정, 성좌 프리즘 발사 위치, 유성 드론 발사 위치가 같은 궤도 계산을 사용한다.
- 크기 패시브를 얻으면 겹치지 않도록 궤도가 자동으로 넓어진다.

이 계산을 무시하고 렌더러에 하드코딩된 `80`, `82`, `94` 같은 반경을 다시 넣지 않는다.

## 7. 쿨다운 HUD

`feature-pack.js`의 초기 `sf2CooldownInfo()`는 구형 장비만 지원했기 때문에 신규 장비의 원형 쿨다운이 멈춰 있었다.

현재 최종 함수는 `performance-guard.js`에서 다음 장비를 추가 지원한다.

- 이온 사슬: `player.ionCd`
- 초신성 코일: `player.novaCd`
- 유성 드론: `player.droneCd`
- 성간 레일: `player.railCd`
- 은하 나선: `player.spiralCd`
- 반사 성좌: `player.mirrorCd`

표시 최대 주기는 반드시 `updateWeapons()`의 실제 쿨다운 계산식과 동일해야 한다.

펄스 블레이드는 지속형 장비이므로 쿨다운 원형을 표시하지 않는다.

## 8. 능력 탭

- 단축키: `I`, `Tab`
- 닫기: `I`, `Tab`, `Escape`, X 버튼, 닫기 버튼
- 플레이 중 능력 탭을 열어도 `state.mode='abilityView'`에 고정하지 않는다.
- 원래 능력 탭 렌더 함수를 호출한 뒤 기존 `playing` 또는 `paused` 모드를 복원한다.
- 플레이 중에는 전투와 렌더링이 계속된다.
- 일시정지에서 열면 일시정지 상태는 유지한다.
- 열 때 키 입력과 터치 이동 입력을 초기화한다.
- 캡처 단계 키 이벤트에서 기존 중복 리스너를 차단한다.
- 레벨업, 보스 보상, 월드 이벤트 등 다른 모달 상태가 시작되면 자동으로 닫는다.
- 재시작과 메뉴 이동 후 내부 `open` 상태가 남지 않는다.

능력 탭이 다시 화면만 멈추고 안 보이는 경우 다음을 검사한다.

1. 후반 파일이 `state.mode='abilityView'`를 다시 쓰는지
2. 키 이벤트가 두 리스너에서 동시에 처리되는지
3. `resetAbilityLedger()`가 열림 상태를 초기화하는지
4. `render.js`가 현재 모드를 그리는지

## 9. 지연 공격 안정성

- `state.runSerial`은 새 런 시작 시 증가한다.
- `scheduleWeaponAction()`은 예약 당시 런 식별자를 저장한다.
- 실행 시 현재 런과 다르면 공격을 버린다.
- 이온 사슬 이중 방전, 초신성 후속 파동, 성간 레일 후속 광선, 은하 나선 시간차 탄막, 에코 추가 발동에 적용한다.

재시작 직후 이전 런의 광선이나 폭발이 나타나면 이 경로를 먼저 확인한다.

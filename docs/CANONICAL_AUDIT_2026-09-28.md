## 2. 런 내부 자원과 영구 재화

### 각성 코어

- `state.awakeningCores`는 **런 내부 임시 자원**이다.
- 영구 저장소 `meta-progression.js`의 통화 키는 `stardust`, `coreShard` 두 종류뿐이다.
- 각성 코어는 Core Development/프로필 지갑에 저장하거나 표시하지 않는다.
- 전투 HUD와 각성 선택 UI에서는 현재 런의 보유량을 표시한다.
- 6중첩 무기 각성 확정 시 1개를 소비한다.
- 런 종료 시 남은 코어는 코어 1개당 기본 Stardust 40으로 환전하고 현재 Stardust 획득 배율을 적용한다.
- 사망, 스테이지 클리어, 메인 메뉴 이탈뿐 아니라 **일시정지 중 게임 다시 시작**에서도 환전하도록 2026-09-28에 누락 경로를 수정했다.
- 스테이지 최종보스는 처치 직후 런이 끝나므로 각성 코어를 지급하지 않는다.
- 각성 기능 활성 상태에서 일반보스는 각성 코어 1개 확정, Stage 중간보스는 35% 확률 1개다. S6 해금 전 또는 설정에서 각성을 비활성화한 상태에서는 각성 코어를 드랍하지 않는다.

### 영구 재화

- Stardust: 일반 영구 성장 및 슬롯/돌파 비용의 주 재화.
- Core Shard: 영구 재화. 현재 성장 노드의 중간/최종 돌파와 장착 슬롯 V·VI에 집중해 사용한다.
- 각성 코어와 Core Shard는 이름이 비슷해도 생명주기와 저장 범위가 완전히 다르다.

## 6. Stage 1~18 및 밸런스 조사

## 6.1 캠페인 기능 해금

- S1 코어 성장, S3 보스 특수능력, **S6 무기 각성 + Endless + Hard**.
- 각성은 S6 최초 클리어 이후 계정 진행도로 유지되어 S1 등 이전 Stage 재플레이에서도 사용한다. 해금 전에는 각성 코어 드랍/HUD 자체를 노출하지 않는다.
- S12 일반 레벨업 4지선다, S18 다중 투영 일반 레벨업 풀 진입 + 최대 중첩 2→3.
- S14는 **선행 재구성 +3**으로 확정했다. 이후 모든 런에서 실제 일반 레벨업 선택 3회를 전투 시작 전에 처리해 Lv.4로 시작한다. `render.js`의 재시작/재도전 핸들러도 함수 참조를 미리 고정하지 않고 클릭 시 최신 `resetGame()`을 호출하도록 수정해 후발 reset 래퍼를 우회하지 않는다.
- S16은 **코어 성장 3차 돌파**로 확정했다. 생명 코어/출력 증폭기만 Lv.12까지 열고, 주기·자석·피해 감소·성진 수급은 기존 최대치를 유지한다.
- S3 이전 일반보스는 특수능력 대신 현재 보유 무기/패시브 +1을 준다. S3 이후부터 기존 trait/weapon augment 선택창을 연다.
- 설정 > 해금 관리는 접기/펼치기로 만들고 자동 적용형 5종(각성/특수능력/4중 재구성/선행 재구성 +3/다중 투영)만 ON/OFF한다. 코어 성장·Endless·Hard·3차 돌파처럼 직접 선택해야 적용되는 시스템은 목록에서 제외한다.
- 이벤트는 해금 대상으로 삼지 않는다. Endless 이벤트 풀은 기존 성운 보관소/추락한 우주선/공허 균열에 **조난 신호·유성 광맥·포식성 성운·중계기 복구·항성 폭풍의 눈**을 추가해 8종이 됐다. 현상금 신호/중력 난파장은 제외했다. Endless는 이벤트별 개별 재등장 시계 + 공통 최소 58초 게이트를 함께 사용한다. Stage config는 여전히 randomWorldEvents=false지만, 별도 `STAGE_WORLD_EVENT_PLAN`으로 S1 보관소·S2 조난·S3 우주선·S4 유성·S5 포식성 성운·S6 중계기·S7 폭풍·S8 공허 균열을 순차 첫 등장시키고 이후 재사용한다. Boss Rush는 현재 미구현/추후 검토다.

### 전체 압박 곡선

각 Stage runtime의 원시 `spawnProfile`은 후반으로 갈수록 cap 증가/rate 감소 구조지만, 실제 런타임은 공통 `stageSpawnBudget()`가 다시 제한한다.

- 성능 tier와 compact 환경에 따라 상한을 낮춘다.
- 일반 동시 생성 count는 최대 2로 제한한다.
- 후반 Stage의 원시 cap 80대 값이 그대로 동시 적 수가 되는 구조가 아니다.
- Stage 환경 기믹은 별도 진행도 스케일을 사용한다. S1~3 초반은 기준 피해 약 56%·느린 속도·긴 경고로 시작하며 후반 Array 진행 후반은 최대 약 122%까지 상승한다. 이 스케일은 환경 컨텍스트에만 적용되며 보스 공격에는 적용하지 않는다.
- 경험치 결정은 새 XP 생성 시 주변 결정과 선제 병합하되 **플레이어에 더 가까운 결정을 남기고 먼 결정의 값을 안쪽으로 흡수**한다. 140/90개 hard cap도 거리순으로 가까운 결정을 보존한다.
- 기존 구조는 Stage 6/12/18만 진행도 32%/62%에 중간보스 2회, 나머지는 46% 중간보스 1회였고 일반 보스는 전혀 없었다. 고정 이벤트 역시 대부분 wave 2회 + hazard 3회 + 최종보스의 동일한 큰 박자를 공유해 체감 단조로움의 원인이 됐다.
- 2026-09-29 재교정에서 Stage 서브보스 스케줄을 **M→M→B 반복**으로 통일하고 후반 묶음 수를 크게 늘렸다. S1~2는 2+1, S6은 6+3, S12는 10+5, S18은 16+8이며 동시 조우 상한은 Route 3 / Bloom 4 / Array 5다.
- 서브보스 조우 수와 별자리별 공유 풀은 유지하되, **공용 `stageEncounterSignature` 제거**로 Route/Bloom/Array 공통 공격 덧씌우기를 폐기했다. 6종 중간보스와 8종 일반보스는 각각 독립 기술 세트를 사용한다. XP는 추가 전투 수만큼 정상 지급하며 각성 코어는 일반보스 확정 1개, Stage 중간보스 35% 확률 1개다. 쌍둥이형 조우는 보상 중복을 막는다.
- 보스 HUD는 살아 있는 조우를 하나씩 별도 HP 바로 표시한다. Mirror 등 twinGroup은 한 조우로 합산하고 최종 초월체를 최상단에 둔다. 타이머/위협/Stage 목표와 보스 이름이 같은 세로 영역에서 겹치지 않도록 보스 HUD 시작 위치를 아래로 분리했다.
- Stage 최종 초월체 처치 콜백이 누락되더라도 런이 영구 진행 상태로 남지 않도록, `run.bossSpawned` 상태에서 최종 보스 ID의 생존 여부를 매 프레임 재확인하고 사망/소실 시 `beginStageVictory`를 호출하는 복구 경로를 추가했다.
- Stage 이벤트는 정예가 없는 순간에만 표식을 생성하고 이벤트 진행 중에는 Stage 정예 스폰을 잠시 보류한다. 한 Stage에 여러 이벤트를 배치하며 후반으로 갈수록 배치 수가 증가한다.
- Stage 최종 초월체의 공용 manifested 공격층은 폐기했다. `STAGE_APEX_UNIQUE_TECHNIQUES`에 Stage 01~18 전용 함수 18개를 두며 `stageBossManifestedTechnique`, 공용 blaster/tentacle/rift attack helper는 존재하지 않는다. 정지 플레이어 안전지대를 줄이기 위해 현재 위치·과거 위치·실제 이동축을 직접 읽는 전용 기술을 분산했다.
- 성좌 최종 Stage 보스는 일반 Stage 보스보다 HP +18%, 피해 +6%, 주요 주기 약간 단축.

코드상 압박 증가는 급격한 단일 점프보다 점진적으로 구성되어 있다. 다만 **플레이어의 실제 성장 속도·무기 운·난이도 선택까지 포함한 공정성은 정적 코드만으로 확정할 수 없으며 실플레이 표본이 필요하다.**

## 7. 스테이지 배경

Stage 1~18 배경 구조는 미구현이 아니었다.
- 1~6: route / 파편의 항로

정적 별/그라디언트는 캐시할 수 있지만 월드 구조는 플레이어 좌표에 따라 이동한다. 최근 문제는 주요 구조물까지 희미한 field alpha를 상속해 실제 화면에서 거의 보이지 않던 것이었고, 주요 랜드마크 가시성을 별도로 복구했다.

- `runtime-config.js`: core 및 후속 12종을 조건부 추가.
- 일부 후단 파일이 속성까지 보정한다.

현재 동작 자체를 깨는 오류는 확인하지 않았지만, 이름/아이콘/기본값이 파일 간 드리프트할 위험이 있다. 향후 구조 정리 시 **동작·디자인 변경 없이 단일 정본 데이터 테이블로 합치는 작업**을 별도 마이그레이션으로 다루는 것이 안전하다.

### 전역 함수 래퍼 체인

정적 스캔에서 핵심 함수 재할당 래퍼가 여러 계층에 남아 있다. 특히 reward/endgame/community/performance/awakening 모듈이 `updateWeapons`, `dealDamage`, `updateWells`, `draw*`, `endGame`, `resetGame` 등을 순차 래핑한다.

이는 현재 Stackfall의 가장 큰 회귀 위험 중 하나다.
- 후단 래퍼가 이전 함수를 호출하지 않으면 기능이 조용히 사라질 수 있다.
- 최적화가 상위 보상/각성 래퍼를 덮어쓸 수 있다.
- 각성 BASE/AWAKE 소유권을 잘못 읽으면 기본 디자인에 각성 디자인이 누출될 수 있다.

따라서 대규모 구조 변경 전까지는 기존 소유권 계약과 load order를 유지하고, 래퍼를 새로 추가하기보다 기존 최종 소유자 안에서 수정하는 것을 우선한다.

### 현재 중요 load order

후단 핵심 순서:
`meta-upgrades.js → weapon-awakening.js → A1-A7 → A8-A13 → A14-A19 → dev-tools.js → canonical-weapon-visuals.js`

`canonical-weapon-visuals.js`가 현재 마지막 runtime script이며 기본 투사체·방벽·중력·공전 무기 일부의 최종 시각 소유권을 가진다.

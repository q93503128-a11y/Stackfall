## Stage 1 review

4개의 실제 몸체 OBB를 렌더·무기 적중·접촉이 공유한다. 공격 물체는 최대 6개, 경고와 실제 이동을 구분한다. 모바일 셔터의 통로는 최소 100px이며 크기 축소 후에도 주 실루엣을 유지한다. GPU가 담당하지 않는 독립 물체는 단일 Canvas에서 그대로 그린다. 60Hz 고정 시뮬레이션으로 x2는 두 번의 동일한 물리 스텝을 실행하며, 고속 공격에는 segment 검사를 적용한다. 스테이지 시작·보스 프리뷰·페이즈·격파에서 잔류 물체를 정리한다.

검증: Stage 1 40/40, 실제 geometry 12개, 전 Stage 계약과 공용 회귀/ownership, 전체 src syntax. 실제 Chromium 1440×900 GPU 및 Canvas, 390×844 Canvas에서 정상 4:55→5:00 트리거, 등장, 4개 공격, 48% 전환, 격파 본체 렌더 호출과 보상 결과를 검사한다. 스크린샷을 직접 확인한다. 테스트는 상용 음원 품질이나 타 게임보다 뛰어난 재미를 보증하지 않으며 최종 실플레이 평가는 별도로 필요하다.

기존 stale 검사 정정: save schema 6, 이벤트 8종과 현 간격, S18 다중 투영 3중첩 해금, 실제 드론 raster 178×78, 달 궤도 .56초, 현재 메타 수치표/결과 그래프 DOM, 보스 HUD 145px, GPU 30/40/50/60fps, Windows 줄바꿈. 실제 기능은 변경하지 않았다. 별도로 공용 foreground 경로가 승리 렌더 호출을 누락하던 실제 오류를 수정했다.

## Stage 2 design review (before implementation)

1. 핵심: S1 출구의 이온 유체가 거대한 순환기관으로 이어지는 살아 있는 해구. 2. 공간: 중첩 성운 앵커는 유지하고 연속 굴곡 양안과 아래로 흐르는 심층 층을 추가한다. 3. 진행: 65초 압력 증가, 185초 심층 진입, 250초 유맥 가속, 295초 두 심실의 먼 맥박; 개발 시각으로 복원 가능하다. 4. 일반 기믹: 전단 예고 뒤 실제 이온막이 폭을 유지하며 가로질러 흐른다. 5. 조우: 기존 M→M→B와 성운 보관소 유지; 유체 공격은 예고하고 물리 벽을 두지 않는다. 6. 정체성: 해구 전류를 공급하는 순환기관. 7. 실루엣: 비대칭 두 심실과 불규칙 유맥, 정오각 방사 대칭 제거. 8. 등장: 양안의 유체가 서로 다른 속도로 응집하고 같은 심장 몸체를 형성한다. 9. 전투장: 벽 없는 유체 해구; S1 봉쇄장과 구분. 10. 이동: 관성 있는 해류 표류, 모바일에서는 부드러운 가시 범위 보정. 11. 페이즈: 68% 양 심실 분리 / 32% 편심맥·역류. 12. 공격: 유맥 순차 방전, 눈에 보이는 흡기→방향 분출, 큰 구체를 운반하는 횡류. 13. 실물: 흐르는 막·액적과 실제 심실 수축. 14. 경고: 유맥 점등·흡기 흐름·도달 방향, 동작 토큰으로 취소. 15. 전환: 틈이 벌어지고 각 심실이 다른 리듬으로 움직이며 흐름 반전. 16. 격파: 심장이 부풀어 찢어진 뒤 청록/자홍 유체가 반대 방향으로 빠지고 해구가 맑아진다. 17. 연결: 잔류 응결 결정이 S3 유리별 묘역의 전조.

자기검토: S1의 금속 OBB·격벽·강체 돌진을 재사용하지 않는다. S2에는 hard arena를 만들지 않는다. 기존 visualR64 / hitRadius92 / contactR64를 유지하며 주요 유맥 끝은 공격 피격 범위 안에 둔다. GPU의 원형 hostile sprite가 전용 액적을 덮지 않도록 실제 최종 draw owner를 확인한다. 기존 보상·330초 등장·적·이벤트 횟수는 유지한다.


## Stage 2 implementation review

S1의 봉쇄/강체 문법을 복제하지 않고 wall 없는 유체 공간으로 완성했다. 배경의 연속 굴곡 양안은 S1의 직선 항로와 다르며 4개의 시간 기반 환경 상태는 개발 프리뷰에서도 복원된다. 기존 성운 캐시와 성운 유영체를 유지한다. 이온막은 예고 후 움직이는 실제 판정, 액적은 GPU에서도 전용 드로잉으로 보존한다. 심실 외장과 이동을 모바일에서 확인하고 화면 내 전체 hit envelope를 검사한다. 68/32%에서 이전 예약 행동을 취소한다. 동일한 몸체가 등장/전투/배액 격파를 담당한다.

검증: Stage 2 계약 30개, 전 Stage·공용 회귀·ownership·전체 syntax·fingerprint. 실제 Chromium GPU/Canvas/모바일에서 5:25→5:30 정상 트리거, 3개 공격군, 두 페이즈 전환, radius 64/92/64 분리, 배액 렌더와 클리어 결과. 실제 음원 녹음/청취를 통한 음악 품질 평가는 아직 수행하지 않았다.

## Stage 3 design review (before implementation)

1. 핵심: 해구에서 응결한 별을 보관하는 결정 묘역. 2. 공간: 행렬 타일 대신 드문 길쭉한 묘표와 높이가 다른 결정층. 3. 진행: 투명층 노출→각인 점등→묘표 균열→중앙 석관 부상. 4. 기믹: 결정의 굴절 분열과 실제 하강 결정. 5. 조우: 유리날개와 기존 조우/추락 우주선 일정은 유지하고 결정층 사이에서 전투. 6. 초월체: 묘역의 빛을 가두는 성물함. 7. 실루엣: 길쭉한 비대칭 육면 석관, 공전 날개 제거. 8. 등장: 수직 묘표에서 같은 몸체가 들어 올려짐. 9. 전투장: 벽 없는 묘역, 드문 묘표는 장식이고 위험 결정만 판정. 10. 이동: 독립된 세 묘표 사이에서 예고 후 가속·제동. 11. 페이즈: 52% 뚜껑 분리. 12. 공격: 결정 강하 / 굴절 분열 / 뚜껑 개방 절단. 13. 실물: 삼각 결정과 길쭉한 결정 뚜껑. 14. 경고: 실제 도달 외곽과 움직임 준비 자세, 경고 중 무피해. 15. 전환: 뚜껑이 벌어져 내부 수직 틈 노출, 공격 순서 변화. 16. 격파: 석관이 층별로 박리되어 묘역 아래로 가라앉고 각인 소등. 17. 연결: 남은 정지 결정이 S4 시간 회랑의 고정점.

자기검토: S1 격벽/인양·S2 유체막/방향 액적과 다른 다각 결정, 이동은 플레이어 공전이 아니다. 실제 다각형을 몸체와 공격의 공통 판정으로 쓰며 GPU 캐시가 외형을 바꾸지 않게 최종 렌더 소유자에 등록한다. 기존 360초·해금·보상·유리날개는 보존한다.


## Stage 3 implementation review

S1 관문·강체 봉쇄, S2 두 심실·해류와 비교해 수직 결정 석관·독립 묘표 이동·굴절 분열을 선택했다. 행렬 타일 경로를 우회하고 고정 성묘 및 불규칙 묘표를 전용 렌더로 그린다. 몸체 다각형은 무기/접촉에 동일하며 빈 외곽 원은 판정하지 않는다. 공격은 6개 상한·경고 후 실제 이동·상대 swept segment, 페이즈 변경은 예약 행동 토큰을 취소한다. 등장/전투/격파는 같은 몸체를 사용하며 GPU/cached 경로에서도 전용 draw owner가 호출된다.

검증: Stage3 14/14, geometry 16개, 전체 Stage/공용/ownership/syntax PASS; Chromium GPU·Canvas·390px 모바일 각각 PASS, 정상 5:55→6:00, 세 공격, 구조 전환, 외장 피격·고속 segment, 격파 실제 draw 및 HUD 정리·클리어. 화면 직접 검토 후 면 명암과 성묘 보강. S2 최종 캡처의 일회 시간 초과는 재실행에서 세 경로 모두 통과(인프라 일시 오류); 게임 실패로 분류하지 않는다. 음악 장면 코드만 검증했으며 청취 평가는 남는다.
